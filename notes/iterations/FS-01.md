# FS-01: regular-file truncate and ftruncate

- Status: implemented; exact-commit Woodpecker and guest acceptance pending
- Base SHA: `5374fad`, freshly fetched `origin/main`
- Branch: `work/FS-01`
- Hypothesis: both path and descriptor truncation can resize the same RAMFS node
  atomically, preserve all open offsets, and zero newly visible bytes without
  breaking older VFS adapters.

## Scoped design decisions

Reviewed `notes/design/FS-01.md` at `937c61a` with coordinator corrections:

- Include the `off_t` typedef with these two libc wrappers.
- Append API functions after the actual base tail (`environ_location`); another
  worker's PENV-03 append must be reconciled by the integrator before merging.
- Append optional node truncate operation while retaining the old node-table
  prefix contract. Guard the optional member by `struct_size` before reading it.
- Missing path node operation returns `ENOSYS`; missing descriptor file operation
  returns existing `EBADF`. Pipes/terminals use explicit `ESPIPE` callbacks.
- Read-only descriptor truncation returns `EBADF`, directories `EISDIR`, negative
  or size_t-unrepresentable lengths `EINVAL`; mode-bit enforcement stays deferred.
- Growth checks capacity arithmetic and allocator failure before publishing any
  node changes, then zeroes the entire newly visible span. Shrink retains capacity.
- Tests include successful path truncation observed through an independently
  open descriptor whose offset remains unchanged, shared dup/task visibility,
  allocation failure, and old-sized/NULL optional adapter behavior.

## Change and review

- Implementation: two appended API operations and thin ordinary libc wrappers;
  shared VFS dispatch with optional callback guards; one RAMFS resize operation
  preserves offsets and failure atomicity, and zeroes newly visible bytes.
- ABI, ownership, cleanup: existing members stay in place; old node prefixes
  install and resolve normally, optional tail access is bounded, and open/unlinked
  lifetimes stay with the existing node references. No upstream source changed.
- Documentation: SPEC.md, LIBC.md, this iteration note
- Bounds: size_t-narrowing and maximum 32-bit capacity cases are conditional
  on 32-bit hosts; the observed local suite uses 64-bit arm64 Linux.
  Regular RAM files only; no host mounts, mode enforcement, fallocate,
  hard-link semantics, or other filesystem operations.
