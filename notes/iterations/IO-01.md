# IO-01: Descriptor Readiness Polling

## Goal
Implement the core non-blocking readiness detection interface (`poll`) across all supported descriptor types (pipes, files, and console). 

## Implementation
Following the decisions established in `IO-01-design`, the `poll` API allows tasks to synchronously evaluate or safely block on descriptor availability.

Key design points correctly integrated into the engine:
- **API and Header Exposure:** Created `<poll.h>` mapping `poll` and `struct pollfd` structures using the `cb_libc` binding. 
- **Backwards Compatibility:** Adjusted the `api_is_usable` linkage validation logic to correctly treat a `struct cb_api_v1` that shrinks exactly to the pre-`poll` boundaries (`offsetof(..., poll)`) as a fully compliant, older-versioned table. Attempts to call `poll` on this degraded mock API cleanly return `-1` mapped to `CB_ENOSYS`. 
- **Event Scoping:** Adjusted the internal pipe-read logic to properly mask readiness. Unconditional signals (`CB_POLL_HUP`, `CB_POLL_ERR`) are strictly reported even if `CB_POLLIN` / `CB_POLLOUT` aren't requested, satisfying proper edge triggers on teardowns.
- **Clock Dependency and Timeouts:**
  - Tasks specifying an elapsed deadline (`timeout > 0`) measure their precise boundary using the host's monotonic `monotonic_millis()` interface upon system call entry.
  - If the host environment does not possess a monotonic clock (returning `0` on entry or mid-wait), the kernel aggressively aborts the loop, explicitly reporting `-CB_ENOSYS` to avoid silently mutating finite demands into infinite locks.
  - Standard zero-value readiness and indefinite `-1` requests natively ignore the clock safely.
- **Scheduler Interleaves:** Re-configured `cb_kernel_run`'s idle loop. Tasks blocked on `CB_TASK_BLOCKED_POLL` are tracked to compute the minimum global wake timeout. The scheduler dynamically delegates this precise bounds to `host->console_poll(...)`, seamlessly ensuring timely wakeups without indefinite spins or CPU burning.

All explicit exact-head CI requirements were executed with memory leak checks passing cleanly.
