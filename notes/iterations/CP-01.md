## 3. Four CP-01 Specific Findings & Architectural Confirmations

1. **Zero Process Model Dependencies:**
   - Audit and code analysis confirmed NetBSD `cp` makes 0 calls to `vfork`, `fork`, `exec*`, `spawn`, `system`, or `popen`.
   - `cp` executes recursive copying entirely in-process using `fts(3)` directory traversal and VFS `mkdir`/`open`/`read`/`write`.
2. **`fcpxattr` Scoping:**
   - `fcpxattr` in `utils.c` is only invoked when `pflag` (`-p` / `-a`) is set.
   - Standard file copying, recursive copying (`-r` / `-R`), and forced overwriting (`-f`) never reach `fcpxattr`.
   - In accordance with task constraints, `-p` / `-a` is excluded from the accepted behavioral matrix.
3. **`FTS-CORE-01` Surface Completeness:**
   - Analysis of `cp.c` confirmed that directory traversal exclusively uses the 4 entry points established by `FTS-CORE-01`: `fts_open`, `fts_read`, `fts_set(FTS_SKIP)`, and `fts_close`.
   - `fts_children` is never called by `cp.c`.
4. **`cb_libc_mkdir` Restoration on Measured Demand:**
   - `cp.c:482` requires `mkdir(path, mode)` to recreate directory hierarchies during recursive copy.
   - `cb_libc_mkdir` was restored to `libc/cb_libc.c` and wired cleanly to the existing VFS `api->mkdir` (`cb_vfs_mkdir_path`).
   - Zero modifications to `include/cannedbsd/abi.h`.

## 4. Chunked I/O & `mmap` Fallback

- `sys/mman.h` declares `mmap`, `munmap`, `madvise`, `MADV_SEQUENTIAL`, `MAP_SHARED`, `MAP_FILE`, `MAP_FAILED`, and `PROT_READ`.
- `cb_libc_mmap`: returns `MAP_FAILED` (`(void *)-1`) with `errno = ENOSYS`. NetBSD `cp` (`utils.c:198-256`) uses `mmap` as an un-guarded fastpath for non-empty regular files $\le 8\text{MB}$, but cleanly and silently falls back to chunked 64KB `read()`/`write()` loops when `mmap` returns `MAP_FAILED` (no diagnostic, no abort).
- `cb_libc_munmap`: returns `-1` with `errno = ENOSYS` (honest failure; returning 0 would be fabricated success).
- `cb_libc_madvise`: returns `0`. `madvise` is explicitly advisory by POSIX/BSD specification; accepting advice as a no-op is conforming behavior, not a claim about work performed.

## 5. Metadata Setters & Failure Honesty

- Unimplemented metadata operations fail detectably rather than fabricating false success:
  - `cb_libc_lutimens` / `cb_libc_futimens`: return `-1` with `errno = ENOSYS`.
  - `cb_libc_lchown`: returns `-1` with `errno = ENOSYS`.
  - `cb_libc_chflags`: returns `-1` with `errno = ENOSYS`.
  - `cb_libc_link` / `cb_libc_symlink`: return `-1` with `errno = ENOSYS`.
  - `cb_libc_readlink`: returns `-1` with `errno = EINVAL`.
  - `cb_libc_mkfifo` / `cb_libc_mknod`: return `-1` with `errno = ENOSYS`.
  - `cb_libc_chmod` / `cb_libc_lchmod`: return `-1` with `errno = ENOSYS`. Unlike `fchmod` in MV-01 (where `open(..., O_CREAT, mode)` set permissions at creation), NetBSD `cp` calls `chmod` on directories upon post-order ascent (`cp.c:521`) casting to `(void)chmod(...)` (which ignores the return), and in `setfile()` (`utils.c:386`) under `-p` (which detectably fails and warns). Returning `ENOSYS` is honest and keeps permissions deferred without breaking unflagged `cp`.
  - `cb_libc_getuid`: returns `0`. POSIX `getuid` has no error return by contract and cannot fail; `0` is the honest representation of a runtime with no user model and a single implicit identity.
  - `cb_libc_umask`: tracks and returns previous process mask (default `022`).
