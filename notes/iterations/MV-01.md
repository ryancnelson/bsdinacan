## 3. Four MV-01 Criteria Validation

1. **Re-measure first:** Recorded initial compile diagnostic against `f932161` (`sys/extattr.h: No such file or directory`) before creating headers.
2. **Extattr / `fcpxattr` handling:** `fcpxattr(from_fd, to_fd)` returns `-1` with `errno = ENOSYS`. On same-mount moves, `rename()` succeeds without calling `fcpxattr`. On cross-mount moves (`EXDEV`), `fastcopy` executes the fallback copy, calls `fcpxattr`, emits the standard non-fatal warning to stderr, and completes the copy+unlink cleanly.
3. **Rename priority:** Unconditional invocation of `rename(from, to)` as the primary fast path; `fastcopy` is entered only on `EXDEV`.
4. **Deferred permissions:** User/group name resolution (`user_from_uid`, `group_from_gid`) and `strmode` formatted prompts are implemented to satisfy prompting semantics without introducing speculative permission enforcement or fake authentication layers.

## 4. Invariant 4 Clarification (Ancestor Retain Lifetime vs Copied Inodes)

- Storing copied 64-bit scalar inodes (`st_ino`) simplifies cycle detection to integer comparisons and eliminates dangling pointer risk.
- Maintaining the stack frame pointers (`fts->stack[depth].dir = dir = opendir(...)`) is strictly load-bearing for:
  1. Stream resumption when popping back up the directory tree for post-order processing and subsequent `readdir()` calls.
  2. Symmetric resource lifecycle cleanup in `closedir()` upon ascent and in `cb_libc_fts_close()`.
